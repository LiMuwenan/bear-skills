# Conversation Archive

按会话归档对话中的解释性信息。代码与测试是事实来源，本 skill 只记录「为什么这样做」。

## 铁律（优先级最高，违反即本次归档无效）

1. **不编造**：每条记录必须能在本会话原文中找到依据。找不到依据的内容一律不写。
2. **不遗漏**：属于「必记清单」的内容必须落盘，不能因为「看起来不重要」而跳过。
3. **不臆想**：不补全未讨论过的背景、动机、影响范围。不确定就写 `（待确认）`。
4. **不添油加醋**：用原话或中性陈述，不加「显然」「因此」「大大提升」这类评价性修饰；不合并两次独立讨论，不把推测写成结论。

每次追加完逐条自查：这句话在对话里出现过吗？没有就删。

## 触发时机

- **每轮对话执行一次判断**：本条用户消息或本次回复中，是否产生了「必记清单」里的内容。
- **有则立即写入**，不等用户提醒、不等会话结束。
- **不创建空记录**：新会话尚未产生实质对话时不创建文件、不写任何内容。文件在首次出现可记录内容时才创建。
- **收尾触发归档总结**：用户说「归档 / 总结这次会话 / 收尾 / 先到这 / 结束了」时，执行一次 snapshot，把已有记录归纳成归档总结。
- 纯问答、查阅资料、闲聊：不记录，也不创建文件。

## 必记清单（出现即写入，不得跳过）

1. 技术选型或架构决策：选了什么、为什么、放弃了什么、代价是什么
2. 需求变更：原需求 → 新需求 → 变更原因
3. 讨论并放弃的方案：尝试过什么、为什么放弃、重启需注意什么
4. 新的术语、角色、模块代号及其含义
5. 未完成项、已知风险、待人工确认的点
6. 约束条件：预算、性能指标、合规/安全要求、技术栈或版本限制、必须兼容的既有系统
7. 用户的长期偏好与约定：如「以后都用中文注释」「不要新增依赖」「别用 ORM」这类跨会话有效的规则
8. 被纠正的错误假设：agent 理解错了什么、正确理解是什么
9. 开放问题：已提出但尚未决策的事项，与「已定待做」的待办区分
10. 外部契约变更：API 字段、事件格式、表结构、第三方服务或依赖版本的调整

## 明确不记

- 查阅资料、搜索结果、文档摘录本身
- 查阅项目、读代码、探索仓库、grep 查找的过程与发现（除非该发现直接推翻了某个既定方案，此时只记「方案变更」，不记代码细节）
- `git commit`、切换分支、合并、拉取、推送等操作
- 工具执行输出、报错日志原文（除非它直接导致了一个决策，此时只记决策本身）
- 依赖安装、环境搭建、工具配置的过程
- 文件重命名、移动、格式化等机械改动
- 闲聊、寒暄、格式调整、错别字修正

## 文件规则

- 路径：`docs/agent-log/YYYY-MM-DD-<session-id>.md`
- 日期与会话 id 取**文件首次创建时**的值，之后永不改名。
- 同一会话跨天继续写入同一个文件，不新建。
- 会话绑定关系保存在 `docs/agent-log/.current-session.json`，不要手工编辑或提交。
- 默认目录 `docs/agent-log/`；若项目已有 `docs/adr/` 或 `docs/decisions/`，先询问用户用哪个，不要擅自建第二套目录。
- 文件分两层：**上方是 append 原始记录，只增不改，任何模式都不得修改或删除**；末尾是 `## 归档总结`，由 snapshot 生成，允许整节替换。

## 操作步骤

### 1. 取得当前会话的归档文件

```bash
python scripts/archive.py open --topic "<会话主题>"
```

- 本会话首次归档时加 `--new-session`，否则会复用上一次会话的文件。
- 若运行环境提供了会话标识，可加 `--session-id <id>` 显式指定。
- 命令只输出文件路径；文件不存在时按模板创建。
- 已有绑定且文件存在时直接复用，跨天也不换文件。

### 2. 追加记录

用编辑工具在文件末尾追加一段，格式：

```markdown
## 2026-11-12 14:30

- **[决策·已定]** 选 X 而不是 Y。理由：…；代价：…
- **[决策·暂定]** 暂定 X，若 … 则改回 Y。
- **[变更]** 原需求 A → 新需求 B。原因：…
- **[放弃]** 方案 C。放弃原因：…
- **[术语]** `Foo` = …
- **[约束]** 必须兼容 Node 18，不能引入原生依赖
- **[偏好]** 注释一律用中文
- **[纠正]** X 不是…，正确是…
- **[开放问题]** 选 A 还是 B，待 … 后定
- **[契约]** `/api/user` 的 `name` 拆成 `first` / `last`
- **[待办]** …（负责人 / 截止）
- **[风险]** …（触发条件 / 缓解措施）

> 依据：用户「…」；Agent「…」
```

- 标签固定为上面 11 种，不得自造同义词。
- 决策必须标注状态：能立即执行、无待验证条件的用 `已定`；带前提或待验证的用 `暂定`。
- **决策被推翻时，不修改旧记录**，新增一条 `**[变更]**`，写明「推翻 <时间戳> 的 <决策>」并给出新理由。
- 只写本轮真实产生的内容，没有的类目直接省略，不要留空占位。
- 每段必须带「依据」行，引用能支撑该结论的原话，每条不超过 3 行。
- 同一轮的多条内容合并到同一个时间戳小节下。
- 涉及代码时只保留能说明决策的最小片段，完整代码引用 commit hash。

### 3. 归档总结（snapshot）

用户要求归档 / 总结这次会话 / 收尾时执行。

1. 读取当前会话文件的全部 append 记录。
2. 归纳成结构化总结，**只使用上方记录里已有的信息**，不引入新内容。
3. 追加到文件**末尾**，位于所有 append 记录之后；不得新建文件。
4. 若文件末尾已存在 `## 归档总结`，整节替换为新总结；**append 记录一个字都不能改**。
5. 若总结与某条 record 冲突，以 record 为准，并在总结中标注 `（与记录不一致，待确认）`。

格式：

```markdown
## 归档总结

> 生成时间：2026-11-12 18:00｜依据：本文件上方 N 条记录

### 背景

### 需求与变更

### 决策

### 术语与角色

### 放弃的方案

### 约束

### 偏好与约定

### 开放问题

### 待办与风险
```

信息缺失的章节直接删除，不要留空标题。

### 4. 更新索引

会话收尾或用户要求整理时执行：

```bash
python scripts/archive.py index
```

脚本会扫描 `docs/agent-log/` 重建 `INDEX.md`，按日期倒序排列。

### 5. 回报

追加成功后用一行说明：`已记录：1 决策 / 1 变更（文件：…）`。
本轮没有可记录内容时，不输出任何归档相关信息。

## 脱敏（写入前强制）

用下面的正则自查，命中即替换为 `<REDACTED: 类型>`：

```
(?i)(api[_-]?key|token|secret|password|passwd|bearer)\s*[:=]\s*\S+
sk-[A-Za-z0-9]{20,}
(?i)\b(?:\d{1,3}\.){3}\d{1,3}\b
[\w.+-]+@[\w-]+\.[\w.]+
1[3-9]\d{9}
```

发现敏感信息时，在回报中说明「已脱敏 N 处」。

## 自检清单（每次追加前）

- [ ] 每条内容都能在本轮对话里找到原文依据
- [ ] 必记清单逐项确认过，没有遗漏
- [ ] 没有添加对话里没出现的原因、影响或评价
- [ ] 不确定的信息标了 `（待确认）`
- [ ] 敏感信息已脱敏
- [ ] 本轮没有可记内容时，没有创建空段、没有创建文件
- [ ] 决策条目标注了「已定」或「暂定」
- [ ] 被推翻的决策用新增 `[变更]` 记录，没有改动旧记录
- [ ] snapshot 只追加或替换归档总结，没有改动任何 append 记录
